## 3. The one finding of the report (negative control) — reviewer's error, model's handling correct
The work document asked for "the edge-only formula for `r·1[r≤H]` vs the true gradient of `r·1[r≤H]`" and expected a mismatch from a "circle term". That is wrong as stated: `∇_x ∫_S f(|x−x'|) dA' = −∮_∂S f n ds` holds for **any** locally integrable `f` (the derivative falls on the indicator of `S`), so the edge-only formula is the *exact* gradient of `∫ r·1[r≤H]`, and a central difference of the oracle value converges to it (the model measured 1.5e-11, correct). What the circle term *is*: that exact gradient of `∫ r·1[r≤H]` equals the cover vector `∫ unit·1[r≤H]` **plus** `H∫ unit δ(r−H)`; the cover vector is the gradient of the *continuous* kernel `(r−H)1[r≤H]`. The model implemented the reading that matches the reviewer's smoke number (1.0 at (1.3, 0.5) = `−H·block_grad(P,0,H)`) and recorded the 1.5e-11 result as a finding: this is the right handling and a good report. `cover.py`'s closing docstring sentence was imprecise and is corrected (commit below); the test is fine as is.
**Fact for later work documents:** do not call the edge-only formula "wrong for discontinuous kernels"; it is exact for the gradient of the integral of *any* kernel; the point of `K = (r−H)1[r≤H]` is that its pointwise gradient is the cover vector.

No polygon clipping. Candidate for WORK-003 (with the "all-neighbour count" `n_w·area(solid ∩ disk)`, which is the existing `Density` operation with the indicator kernel `(1−q)⁰`).
